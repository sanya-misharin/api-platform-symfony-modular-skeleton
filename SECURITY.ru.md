# Политика безопасности

## Как сообщить об уязвимости

**Пожалуйста, не открывайте публичный issue по проблемам безопасности.**

Сообщайте об уязвимости приватно через
[private vulnerability reporting](https://github.com/sanya-misharin/api-platform-symfony-modular-skeleton/security/advisories/new)
GitHub (вкладка репозитория **Security → Report a vulnerability**). Если это недоступно — свяжитесь с мейнтейнером напрямую и дождитесь ответа, прежде чем раскрывать что-либо публично.

Приложите, пожалуйста:

- затронутую версию / коммит и окружение;
- шаги воспроизведения (минимальный proof of concept, если возможно);
- предполагаемое воздействие.

Первичное подтверждение — в течение нескольких рабочих дней. После выхода исправления публикуется advisory, и указывается авторство находки — если вы не предпочитаете остаться анонимным.

## Поддерживаемые версии

Это **стартовый шаблон**, а не версионируемый продукт: исправления получает актуальный `main`. Проект, поднятый из этого скелета, должен определить собственную политику поддерживаемых версий и заменить контакт для репортов выше на свой.

## Область

Сообщайте о том, что может скомпрометировать проект на базе этого скелета — например: обход аутентификации/авторизации, инъекции (SQL/DQL, команд), утечка чувствительных данных, небезопасные дефолты в поставляемой конфигурации, уязвимая зафиксированная зависимость. Находки, требующие уже привилегированного доступа, или затрагивающие только демонстрационный модуль `Example` (удаляется в реальных проектах), — ниже по приоритету.
